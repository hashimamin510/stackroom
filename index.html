Same idea, different places

Stacks at work

Whenever a system needs to remember a “current thing” and return to the most recent unfinished state, a stack is a natural fit.

01 / Software

Function calls

Programs place each active function on a call stack. When it finishes, it is removed and execution returns to the function that called it. Nested calls need this last-called, first-returned order.

02 / Browsing

Back navigation

A browser can keep visited pages in history. Back navigation pops the current page and reveals the most recently visited one, while a forward stack remembers pages you backed out of.

03 / Language tools

Parsing brackets

Compilers and editors push opening brackets as they scan, then pop when a matching closer appears. The top reveals the nearest unmatched opener, which is the one that must match.

04 / Search

Depth-first exploration

Maze solvers and graph searches push paths or nodes to explore. Popping picks the most recently discovered branch, making it easy to go deep and backtrack.

05 / Data

Reversing items

Push a sequence onto a stack and pop it back out to reverse its order. The access rule itself performs the reversal without needing to shuffle each item directly.

06 / Interfaces

Nested dialogs

Navigation flows, menus, and modal screens can stack on top of one another. Closing the top layer returns people to the screen immediately beneath it.
